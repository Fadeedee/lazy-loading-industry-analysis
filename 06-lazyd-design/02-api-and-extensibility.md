# 接口与扩展

> 用稳定的通用语义服务多个调用方，同时保留不影响核心行为的扩展空间。

## 信息分类

| 类别 | 用途 | 示例 |
| --- | --- | --- |
| 核心字段 | 正确供数必需，显式校验 | 内容 ID、大小、来源、会话、使用绑定 |
| Labels | 标记与查询，由调用方维护 | 管理方、应用、环境 |
| Extensions | 命名空间下的结构化调用方信息 | 业务资源关联、调用方自定义版本信息 |
| 行为参数 | 服务明确理解并实施的能力 | 优先级、截止时间、预算、取消、授权与保护策略 |

这是拟议模型，不是对 containerd API 的复制或既有 lazyd schema。协议编码、查询能力及字段名尚待评审。

## 扩展边界

- 核心不解析 `conch.*` 等调用方专有字段，不根据任意 label 决定授权、租约或调度。
- 扩展使用调用方命名空间，并规定编码、版本、键数量、嵌套深度与总大小限制。
- 默认只有对象 owner 或明确授权的主体能读写；更新要有冲突检测，不能整对象覆盖其他主体信息。
- 调用方信息优先挂在会话或其使用绑定上，不改共享内容的身份与 ready 状态。
- 不在 labels/extensions 存储凭据；日志与诊断不能默认输出扩展内容。
- 在允许的格式和容量内，未知扩展可原样保存和返回；未知且会影响正确性的行为选项应明确拒绝或协商，不静默忽略。

## 控制面与数据面

控制面准备内容、建立/关闭使用关系并更新允许修改的属性；数据面处理范围请求及完成。调用方的产品状态不进入每次缺页交互。准备接口需幂等，重试不能破坏已发布缓存；关闭也需处理重复请求。

可选调度提示缺失时使用正常默认策略。提示受授权和预算约束，deadline 是调度输入，不是网络或存储延迟保证。具体数值、协议版本和能力协商待接口选型。

## 测试要求

覆盖无扩展请求、扩展往返、非法/超限扩展、跨 owner 读写拒绝、并发更新冲突，以及未知行为选项的错误语义。使用两个不同调用方命名空间验证核心不依赖产品特征。
