# 运行架构与缺页适配

> 明确单进程如何承载多 VM，以及如何避免下载阻塞事件处理和运行控制。

## 默认运行模型

一个 lazyd 进程管理多个会话及其 UFFD，内部按模块分工：控制接口、pmem 适配、内容核心、下载执行和持久化执行。模块不是独立 binary，也不要求每个会话绑定一个线程。

事件监听使用可并发等待的机制；网络、校验和文件同步通过受限任务/执行池运行，不阻塞 UFFD 接收或关闭通道。实现所用 runtime、队列和任务模型见[选型登记](../04-conch-design-reference/09-core-design-selection.md)，尚未定案。

## 外部 handler 主方案

StratoVirt 注册区域并交接 UFFD 和布局。适配模块验证绑定及运行代次，将 HVA 换算为区域和内容范围；内容核心只处理内容请求。数据可用后适配模块交付文件 FD 和完成范围，StratoVirt 校验并修改自身映射、完成等待。

控制面需要表达来源与绑定已就绪，不能仅以 FD 已发送作为启动门槛。Conch 负责生命周期编排，不接收或转发每个缺页请求。

文件映射是当前主方案的完成方向；具体传输和 wake 顺序仍需真实 KVM 验证。H1 内部 handler 作为主方案出现不可接受成本时的备选，不同时建设两套产品路径。

## 隔离与失败

- 会话、连接、等待者、任务、下载字节、导出 FD 都设置上限及背压。
- 单会话超时只取消其等待关系；公共任务是否继续取决于其他需求及策略。
- 迟到结果必须核对运行代次；已停止的区域不能继续接收映射操作。
- lazyd 退出或连接失效时，VMM 需能在不依赖被阻塞 vCPU 的路径上结束运行并上报，不能只依赖服务端日志。
- 默认不承诺透明重连。若后续增加，必须重新协商 UFFD、区域与使用关系，而非复用旧 FD 数字。

单进程会扩大进程级故障影响范围。需要租户或故障域隔离时可按安全域部署多个实例；实例间共享缓存前须另行解决锁、发布和回收协调，不能直接共同写入同一目录。

## 验收

在不运行 Conch 的条件下接 mock/真实 VMM：多 UFFD 并发、慢下载、同步阻塞、队列饱和、单会话取消、服务退出与 VM stop 均需有界完成。运行模型不以更多 VMM 策略接口为前置。
