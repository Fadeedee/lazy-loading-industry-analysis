# 候选方案与选择门槛

> 明确 pmem 主线、尚待验证的接入细节和可供对照的替代方案；比较候选不等于并行开发所有路线。

当前只读 rootfs 以 EROFS + pmem/DAX 为主线，可写数据保持独立。先完善这条路径及 lazyd 的产品化基础；整盘块/文件服务只作参考，遇到明确阻碍再评估改选，不作为首版退出条件。

## 必须满足的要求

内容正确、授权明确、运行写入隔离、恢复一致、失败可处理、引用可回收。这些来自产品需求，不需要为了每项要求强行找一个“同款项目”。

## 按同一标准比较

| 决策 | 候选 | 先验证什么 | 什么情况下改选 |
| --- | --- | --- | --- |
| 镜像/磁盘布局 | 主线 EROFS pmem + 私有写层；整盘块/文件服务为备选对照 | pmem 的业务延迟、PSS、快照一致性及设备规模 | 出现 guest 不支持 DAX、层数过大或混合布局成本问题后再评估替代 |
| UFFD handler | VMM 内置；外部服务 | 先验证外部交接；内部先作设计/已有实验对照，必要时补原型 | 外部失败隔离/权限过重，或内置路径显著简化生命周期 |
| 页完成 | COPY；只读文件映射；适用 backend 的 memfd 写页 | 不可变 rootfs 的文件映射与 COPY 对照 | remap/UFFD/KVM 边界难以闭合，或收益不足 |
| 内容服务 | lazyd 内容核心 + 会话/来源分离 + 类型适配；已有专用后端按需复用 | 先验证共享任务、有界执行、只读句柄、引用保护，再扩展来源 | 一个适配器的错误会破坏其他对象或格式依赖过重 |
| 启动优化 | 纯按需；工作集预取；缓存范围提前映射 | 分别测，不把“预取”和“映射”混为一个开关 | 额外等待/下载抵消首次业务收益 |
| 内容粒度 | blob；固定块；内容 chunk；组合 artifact | 随机读取、校验依据、跨 VM 共享与索引开销 | 小粒度元数据成本或大粒度下载放大不可接受 |
| Conch 接入 | 原生 source/BootPreparer；snapshotter 契约 | 谁真实拥有 mount、资源状态和回收 | 重复存储 owner，或不得不伪造已完成 unpack |
| 部署隔离 | 节点共享服务；每 VM/session worker | 缓存仍可共享，计算/凭据/失败域分别隔离 | 共享故障或租户边界不可控 |

证据入口：[八个问题](08-design-decisions-and-evidence.md)；机制详解：[产品分析](../02-products/)与[横向比较](../03-design-comparison/)。

## 推荐的第一轮实验组合

选择相同工作负载和镜像内容：

1. 完整本地准备，作为正确性和性能基线。
2. 只读 pmem 按需映射，先验证外部 handler；内部方案仅在具体问题需要对照时补最小原型。
3. 在 pmem 路径上验证 lazyd 两 VM 共享任务、取消隔离、只读导出和资源上限；异常注入与正常读取一起验收。
4. 跑通主线后再分别加入预取与提前映射。整盘对照只在需要回答具体取舍时利用已有后端开展，接入不足先记录，不阻塞主线或另写 VMM 块存储引擎。

这不是要求三个仓先实现三套产品功能。用临时 mock/最小原型确认边界，实验代码不进入产品路径。首版只实现选定的新增路径；复用现有 RAM 恢复，不要求统一所有 handler、传输或迁移接口。StratoVirt 的开发范围受[最小职责](05-stratovirt-responsibilities.md)约束。

## 不可接受的结果

- 缺失数据静默变成零，或覆盖恢复后产生的私有写入。
- 没有可执行的超时/失败策略却允许不可控等待。
- 未授权共享，或者删除一个 VM 导致其他 VM 数据丢失。
- 把当前数据正确误当作重启/掉电后也正确。
- 用未合入 PR、API 名称或本地实验替代整条链路的验证。

不因为某个产品未采纳某 PR，就推断整条技术路线不成立；也不因为相同 syscall 在别处存在，就认定这里已可用。
